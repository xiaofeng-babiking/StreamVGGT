§ 04

Registering a custom dataset

Five steps · BaseMultiViewDataset → __init__.py → train.yaml

Adding a new dataset is mechanically simple — subclass BaseMultiViewDataset, implement two methods, register an import, and add two lines to the YAML. The interesting work is in the data contract: every dataset, no matter how it looks on disk, must return a list of view dicts with the same keys, the same dtypes, and the same coordinate conventions. Get that right and the training loop never knows your loader is new.

1

Create the loader file · subclass BaseMultiViewDataset

Place a new module at src/dust3r/datasets/<your_name>.py. The base class lives at src/dust3r/datasets/base/base_multiview_dataset.py:26 and gives you the sampler, the resolution machinery, the crop / colour-jitter pipeline, and the timestamp-based view sampling. Your job is exactly two methods: _load_data (index the on-disk tree once at construction) and _get_views (materialise num_views frames for a sample).

src/dust3r/datasets/my_lab_scans.pypython
# skeleton for a new multi-view dataset loader
import os, os.path as osp
import cv2, numpy as np

from dust3r.datasets.base.base_multiview_dataset import BaseMultiViewDataset
from dust3r.utils.image import imread_cv2


class MyLabScans_Multi(BaseMultiViewDataset):
    def __init__(self, *args, split, ROOT, **kwargs):
        self.ROOT       = ROOT
        self.split      = split
        self.video      = True         # sequence-style (vs. random-pair)
        self.is_metric  = True         # False if depth is up-to-scale only
        self.max_interval = 8          # sampler stride within sequence

        super().__init__(*args, **kwargs)     # resolves resolution, transform, etc.
        self.loaded_data = self._load_data()
Naming convention The suffix _Multi is conventional for the streaming multi-view variant. The 15 production loaders (Co3d_Multi, ScanNet_Multi, …) all follow it — Hydra will eval() whatever string you put in the YAML, so the class name and the YAML reference must match exactly.
2

Index the on-disk tree · implement _load_data

Called once per epoch construction on rank 0 (or every rank, depending on launcher mode). Its job is to populate five arrays the base sampler relies on. Walk through every scene once, decide which contiguous chunks of frames are valid sequence starts, and stash the answers.

Attribute Type Purpose
self.scenes List[str] Stable scene identifiers (subdir names). Indexed by sceneids.
self.sceneids List[int] Per-image scene-index back-pointer · len == total_images.
self.images List[str] Per-image relative path (joined with ROOT/scenes[sceneids[i]] at read time).
self.scene_img_list List[List[int]] Per-scene ordered list of global image indices. Used by the sequence sampler.
self.start_img_ids List[int] Valid sequence-start indices, i.e. positions i where [i, i+stride…] can yield num_views frames.
Why so many arrays? The flat images / sceneids form is what the batched random sampler iterates over; the scene_img_list / start_img_ids form is what the sequence sampler uses to pick temporally contiguous frames. Keeping both lets the same loader feed either sampling regime.
3

Materialise samples · implement _get_views

Returns a list of exactly num_views dicts, one per frame in the sample. Decode RGB, decode depth, load intrinsics & pose, crop & resize to the chosen resolution, then assemble the contract dict.

my_lab_scans.py · _get_viewspython
    def _get_views(self, idx, resolution, rng, num_views):
        start_id = self.start_img_ids[idx // 10]   # × 10 ≡ re-use start over epoch
        scene_id = self.sceneids[start_id]
        all_ids  = self.scene_img_list[scene_id]

        pos, ordered_video = self.get_seq_from_start_id(
            num_views, start_id, all_ids, rng,
            max_interval=self.max_interval, block_shuffle=16,
        )
        image_idxs = np.array(all_ids)[pos]

        views = []
        for v, view_idx in enumerate(image_idxs):
            scene_dir = osp.join(self.ROOT, self.scenes[self.sceneids[view_idx]])
            rgb_path  = self.images[view_idx]

            rgb       = imread_cv2(osp.join(scene_dir, rgb_path), cv2.IMREAD_COLOR)
            depth     = np.load(osp.join(scene_dir, rgb_path.replace("rgb.png", "depth.npy")))
            depth[~np.isfinite(depth)] = 0
            cam       = np.load(osp.join(scene_dir, rgb_path.replace("rgb.png", "cam.npz")))
            K, pose   = cam["intrinsics"].astype(np.float32), cam["pose"].astype(np.float32)

            rgb, depth, K = self._crop_resize_if_necessary(
                rgb, depth, K, resolution, rng=rng, info=view_idx)

            img_mask, ray_mask = self.get_img_and_ray_masks(
                self.is_metric, v, rng, p=[0.75, 0.2, 0.05])

            views.append(dict(
                img=rgb, depthmap=depth.astype(np.float32),
                camera_pose=pose, camera_intrinsics=K,
                dataset="my_lab_scans",                # ← short stable id
                label=self.scenes[scene_id] + "_" + rgb_path,
                instance=f"{idx}_{view_idx}",
                is_metric=self.is_metric,
                is_video=ordered_video,
                quantile=np.array(1.0, dtype=np.float32),
                img_mask=img_mask, ray_mask=ray_mask,
                camera_only=False, depth_only=False,
                single_view=False, reset=False,
            ))
        assert len(views) == num_views
        return views
4

Honour the view dict contract

Every dict your loader appends must contain these keys, exactly named, with the dtypes shown. Missing or mis-typed keys surface as opaque KeyError / dtype mismatches deep inside the loss code — fix here, not there.

Key Type / shape Required? Convention
img uint8 · H×W×3 BGR must OpenCV BGR layout. Base-class transform converts to tensor & normalises.
depthmap float32 · H×W must Metric depth in metres, or relative depth if is_metric=False. 0 marks invalid.
camera_pose float32 · 4×4 must camera-to-world (OpenCV / right-handed +X right, +Y down, +Z forward).
camera_intrinsics float32 · 3×3 must After the crop & resize — call _crop_resize_if_necessary so K matches the final image.
dataset str must Short stable id used for per-dataset metric reporting. e.g. "my_lab_scans".
label str shouldHuman-readable identifier — usually scene/frame. Surfaces in TensorBoard image titles.
instance str shouldUnique within an epoch. Convention: f"{idx}_{view_idx}".
is_metric bool must Drives whether the loss aligns scale-shift before comparison.
is_video bool must True if frames are temporally ordered; controls the streaming attention mask.
quantile float32 · scalar must Depth-clip quantile for outlier robustness. 1.0 = no clipping.
img_mask bool · H×W must Image-validity (sky, transparent). get_img_and_ray_masks handles defaults.
ray_mask bool · H×W must Per-ray supervision mask (depth-validity ∩ image-validity).
camera_only bool must True for pose-only sources (e.g. RealEstate10K) — disables depth loss.
depth_only bool must True for single-view depth corpora — disables pose loss.
single_view bool must True if the source has no multi-view links across frames.
reset bool must Streaming-state reset flag for the first frame of a new sequence.
The four silent footguns ① Coordinate frame: pose must be camera-to-world; many SfM exports give world-to-camera. Apply np.linalg.inv if needed.
② Depth zero-handling: any non-finite or negative depth pixel must become 0 before assembly; downstream code interprets 0 as "invalid", not "very close".
③ Intrinsics after resize: K must reflect the final image dimensions — always call _crop_resize_if_necessary instead of resizing manually.
④ Length invariant: len(views) == num_views is asserted in the base. If your sampler returns fewer frames, the run crashes at the first iter, not at construction.
5

Wire it in · two files, four lines

Once the loader works in isolation, two registrations make it visible to the Hydra config: import in the dataset module's __init__.py, then reference by constructor-call string in config/train.yaml.

src/dust3r/datasets/__init__.py+1 line
from .wildrgbd import WildRGBD_Multi
from .my_lab_scans import MyLabScans_Multi      # ← add this line
config/train.yaml+1 dataset block, +1 mixture term
# 1) Define the dataset block alongside the other 15:
dataset16: MyLabScans_Multi(allow_repeat=${allow_repeat}, split='train',
  ROOT="../data/train/my_lab_scans",
  aug_crop=16,
  resolution=[(518, 392), (518, 336), (518, 294), (518, 266),
              (518, 210), (518, 154), (392, 518), (336, 518),
              (294, 518), (266, 518)],
  transform=SeqColorJitter, num_views=${num_views}, n_corres=${n_corres_train})

# 2) Add to the mixture concat with a sample weight:
train_dataset: 4500 @ ${dataset1} + 4500 @ ${dataset2} + ...
              + 2250 @ ${dataset15}
              + 1500 @ ${dataset16}                # ← your weight here
Choosing a sample weight The integer is samples drawn per epoch, not a probability. Anchor it against dataset size and signal quality — if your set has 200 scenes of clean metric depth, 1500 is reasonable; for 50 scenes of noisy MVS, maybe 400. The current mixture floor is MVS-Synth at 450; the ceiling is CO3D/ScanNet/ARKit at 4500.
6

Smoke-test before going wide

Drive your loader once in isolation before launching distributed training. A 30-second Python session catches schema bugs that would otherwise stall a 32-GPU job at iteration zero.

standalone sanity check · run from src/python -i
from dust3r.datasets import MyLabScans_Multi

ds = MyLabScans_Multi(
    split="train", ROOT="../data/train/my_lab_scans",
    num_views=10, resolution=[(518, 392)],
    aug_crop=16, transform="SeqColorJitter",
)
print(len(ds), "samples ·", len(ds.scenes), "scenes")
sample = ds[0]                       # list of 10 view dicts
v0 = sample[0]
assert v0["img"].shape[2] == 3          # BGR
assert v0["depthmap"].dtype == np.float32
assert v0["camera_pose"].shape == (4, 4)
assert v0["camera_intrinsics"].shape == (3, 3)
print("✓ schema OK · is_metric =", v0["is_metric"])
Then a 1-GPU dry-run With everything wired, run the full launcher on a single GPU and --num_processes 1 for one print-cycle. If you see the first loss line without an exception, you're safe to scale out.

§ 05

Field notes & methodology

Read before launching ./train.py or ./eval/*/run.sh

On the schema. Every preprocessed frame becomes a tuple of { .jpg, .png, _mask.png, .npz } — RGB, depth as uint16 scaled to maximum_depth, valid mask, and a metadata NPZ holding camera_intrinsics, camera_pose, and the depth scale. Each loader in src/dust3r/datasets/ knows its own minor variation (Hypersim flat _rgb/_depth/_cam, ScanNet's tri-folder color/depth/cam, BlendedMVS using .exr+.safetensor).

On the mixture weight. config/train.yaml:63–65 composes the train set as N @ datasetX. The integer is the number of samples drawn per epoch — not a probability — so adding more datasets grows the epoch linearly. The Share column above is N / 38,750.

On per-sample geometry. Each __getitem__ returns num_views = 10 temporally / spatially adjacent frames at one of ten aspect ratios (long side fixed at 518). The student is asked to reconstruct all ten views jointly; the frozen VGGT-1B teacher provides the supervision target via DistillLoss.

On metric scale. Datasets marked — (rel.) only have relative depth (SfM landmark sparsity or arbitrary-scale MVS). They still contribute through the distillation signal because the teacher's prediction provides a consistent reference frame across the mixture.

On data layout. The expected on-disk root is data/train/<name>/ matching the Path column. On this cluster, the cleanest wiring is a symlink farm pointing data/train/processed_co3d → /jfs/Data_4DFF/train_data/co3d (and so on for the other thirteen). Two slots — ARKitScenes-HR and ScanNet++ — need either new downloads or removal from the mixture line.

On the missing 12 %. ARKitScenes-HR (5.81 %) and ScanNet++ (5.81 %) together account for ≈11.6 % of the mixture. Training without them is feasible — expect a modest dip on high-frequency indoor reconstruction benchmarks (NYU-v2, 7-Scenes). Either fetch later or comment them out of train_dataset:.

On BlendedMVS. The on-disk copy uses .safetensor per-frame instead of the older .npz CUT3R schema. This is a recent revision — verify src/dust3r/datasets/blendedmvs.py parses it before assuming the loader works.

On disk discipline. Total raw download is ≈25 TB across the fifteen sources. The processed CUT3R version is meaningfully smaller (≈12–15 TB). Per-frame IO dominates wall time, not GPU compute — bump num_workers above 12 if your filesystem can sustain it.

On evaluation tasks. Four task families live under src/eval/ — monocular depth (monodepth/), video depth (video_depth/), multi-view reconstruction (mv_recon/) and camera-pose / trajectory (pose_evaluation/). The per-task dataset registry is defined in each subfolder's metadata.py; cross them against the coverage matrix above before invoking ./eval/<task>/run.sh.

On eval data wiring. Eval roots are hard-coded relative to ../data/eval/ in src/eval/*/metadata.py. Mirror the layout from /jfs/guibiao/streamVGGT/data/eval exactly — names are case-sensitive and code expects e.g. data/eval/kitti/depth_selection/val_selection_cropped/image_gathered/ for KITTI, data/eval/sintel/training/{final,camdata_left}/ for Sintel, and data/eval/bonn/rgbd_bonn_dataset/rgbd_bonn_<seq>/rgb_110/ for Bonn's 110-Hz crop.

On Neural 3D Video. Present on disk (single scene, cut_roasted_beef) but not wired into any run.sh. Listed here as an ad-hoc resource — useful for qualitative dynamic-scene demos, not part of the reported benchmark suite.

On metric conventions. Mono- and Video-Depth report AbsRel, δ<1.25 after scale-shift alignment for relative-depth datasets and unaligned for metric ones. MV-Recon reports Chamfer distance, accuracy and completion on the unified point cloud. Pose reports ATE-RMSE and RPE in TUM trajectory format (see traj_format: "tum" in the metadata files).
